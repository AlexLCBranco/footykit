# Phase 1 — report (2026-11-14)

Full per-club table: [phase1-data-check.md](phase1-data-check.md), regenerated by `npm run data-check` (~25 s,
exits 1 if any required check fails).

## Verdict
**ESPN's free, keyless API covers the whole required set for all 54 followed clubs.** No fallback source was needed,
so football-data.org and API-Football were not tested (both also need an account and key).

Followed clubs resolved from config (`config/season.ts`), not hardcoded: 20 Premier League, 20 Brasileirão,
5 La Liga (ATM, BAR, BET, RMA, VIL), 4 Serie A (ROMA, COMO, INT, NAP), 4 Bundesliga (MUN, DOR, RBL, VFB) in this
season's Champions League, plus PSG.

## The endpoint
`site.api.espn.com/apis/site/v2/sports/soccer/all/teams/{id}/schedule` works as reported: without `?fixture=true` it
returns the matches played this season, with it the matches to come, across every competition (league, domestic cups,
UEFA / CONMEBOL, super cups, state championships, friendlies). Each club's feed was cross-checked against every
competition's own scoreboard: no match was missing.

## Architecture answers
**CORS:** ESPN answers `Access-Control-Allow-Origin: *`; a real browser fetch from another origin works (checked in a
real Chromium page). Headless Chromium is refused (403, no CORS header: ESPN blocks the `HeadlessChrome` user agent),
so e2e and perf tests must use recorded fixtures, never live ESPN. Node `fetch` (the data job) is not blocked.

**Refresh:** a once-a-day snapshot is not enough (matches end from ~09:00 to ~01:00 Brazil time). Proposal, two layers:
1. **Season snapshot** (all followed clubs' matches, the competitions' matches needed for tables and brackets,
   standings): GitHub Action every 3 h. ~147 ESPN calls per run; ~3,650 matches → ~576 KB JSON, ~64 KB gzipped.
2. **Day layer** for scores and odds: a same-origin function `api/day?date=` that reads the ~18 competition
   scoreboards for one date and returns only the fields the app reads, CDN-cached 60 s while a match that day is live
   or about to start, 10 min otherwise, 1 day for past dates. The page merges it over the snapshot for the day on
   screen (and tables recompute from it), so a final score shows ~1–2 min after full time while the page is open.
   Same pattern as calendarkit's `api/odds.ts`.

**Where snapshots live — recommendation: Vercel Blob.** The job overwrites one file (`footykit/snapshot.json`): no
git history growth, no deploy per refresh (8 runs a day would be 8 production deploys if committed to `main`). Needs a
Blob store on the Vercel project and its token as a GitHub secret — a Vercel setting, so your yes first. Fallback:
an orphan `data` branch (one commit per run; still grows; trimming it means force-pushes).

**Pipeline (built in Phase 2, from calendarkit's):** snapshot job → slim to the fields the app reads, with a test that
fails if code reads a dropped field → upload → verify step (the public snapshot's `generatedAt` is the new one) →
freshness alarm every 4 h (snapshot older than 7 h, or the day function failing). Logos: a script downloads team and
competition logos once into the repo; the job lists clubs with no local logo (they show a plain disc until added).

## Other findings
- ESPN date ranges (`dates=YYYYMMDD-YYYYMMDD`) currently answer 400; a single day or a whole year (`dates=2026&limit=1000`) works.
- European 2026-27 is ESPN season year 2026; the Brasileirão is a calendar year (2026). Config keeps both per league.
- The club feeds also carry Supercopa de España, UEFA Super Cup, Community Shield, Recopa, Intercontinental Cup and
  friendlies (Phase 2 decides which to show; friendlies probably not).
